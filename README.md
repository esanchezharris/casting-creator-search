# Casting: answer a brief from the roster

A casting tool for a creator agency. Type who a brief needs in plain English;
it searches the roster first and, when the roster is thin, shows which
applicants and prospects would be worth signing for that brief. The query
becomes editable filters plus a topic that is ranked against each creator's
recent posts and CRM notes.

All 178 creators, their numbers and their notes are fictional and generated by
`scripts/seed.py`. The photos and clips are AI-generated stand-ins: nobody in
them is a real person, and the app says so in its footer.

## Run it

    npm install
    npm run dev          # http://localhost:3000

No API key is needed. Without one the app uses the rule-based parser and
keyword ranking. If `OPENAI_API_KEY` is set, in `.env.local` or in your shell,
it uses the LLM parser and the hybrid ranker instead; the page says which
ran, next to the result count.

## What it does

- **Roster first.** Each creator has a pipeline stage: roster (115), applicant
  (40) or prospect (23). With nothing typed, or filters only, everyone is
  listed together. A brief with a topic returns roster creators. If fewer than five
  match, a second group, "Not on the roster yet", lists the applicants and
  prospects who fit. Ask for "applicants", "prospects", "signed" or "not
  signed yet" to search one stage directly.
- **Audience is not location.** "In Florida" filters where the creator lives.
  "Mostly US audience" or "70% US followers" filters where their followers are.
- **Cards** show stage, talent partner, recent reach, engagement, US audience
  and the agreed rate (roster only; everyone else reads "No rate yet"), the
  post or CRM note that matched, and a warning when a conflict note touches
  the topic ("Exclusive with an energy drink brand until March").
- **Scrub preview.** Sweep the pointer across a photo, or drag on a touch
  screen, to flip through a profile without opening it.
- **Quick look.** Space, or a click on the photo or name, opens the profile
  like a post: photo (or a short muted clip with a sound button) on the left,
  posts ordered newest first or most liked first,
  and beside it the post that photo belongs to with its likes and top
  comments, then the numbers, CRM notes and other posts. Passing the mouse
  over the thumbnails flips through them. The arrow keys keep moving between
  creators while it is open.
- **Filters.** A collapsible sidebar holds every filter the search
  understands: stage, creator type and gender as tick boxes with counts,
  followers, engagement and US audience as sliders with a typed box beside
  each, plus place and topic. A typed brief fills it in ("women", "male
  creators" set the gender filter); changing it refines the brief. The chips
  above the grid show how the brief was read and can be removed one by one.
  Sort order sits above the grid.
- **Shortlist.** `S` adds the focused creator. The tray totals reach and cost,
  survives a reload, and "Copy shortlist" produces text for a brand: the brief,
  one line per roster creator with reach, US audience and price, a total, then
  anyone who "would need signing" listed separately.
- **Keyboard.** Arrows move, Space quick look, `S` shortlist, `,` and `.` flip
  photos, `/` back to the search box, Esc closes.

## How well it works

`npm run eval` scores 70 test briefs against 178 creators. All six
combinations were run on 20 Nov 2026: 60 briefs the fixes were developed
against ("tuned") and 10 held out.

| Parser + ranker | Tuned filters | Tuned P@5 | Tuned recall | Tuned nobody-fits | Held-out filters | Held-out P@5 | Held-out recall | Held-out nobody-fits |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Rules + keywords (no key) | 60/60 | 0.88 | 0.77 | 4/4 | 7/10 | 0.86 | 0.86 | 1/1 |
| Rules + embeddings | 60/60 | 0.88 | 0.80 | 1/4 | 7/10 | 0.62 | 0.69 | 0/1 |
| Rules + hybrid | 60/60 | 0.96 | 0.86 | 4/4 | 7/10 | 0.86 | 0.96 | 1/1 |
| LLM + keywords | 59/60 | 0.88 | 0.75 | 4/4 | 7/10 | 0.86 | 0.86 | 1/1 |
| LLM + embeddings | 60/60 | 0.91 | 0.80 | 1/4 | 7/10 | 0.66 | 0.80 | 1/1 |
| LLM + hybrid (default with a key) | 60/60 | 0.99 | 0.84 | 4/4 | 7/10 | 0.82 | 0.96 | 1/1 |

The hybrid ranker lets keywords decide who is eligible and embeddings decide
the order, and falls back to embeddings when the brief is a paraphrase. It
keeps what each does well: "getting better rest at night" finds the five
creators who post about sleep (keywords find none), and "cryptocurrency
trading" returns nobody (embeddings return 22). The held-out set has five
briefs with a topic, so its figures move a lot on one brief.
[docs/EVAL.md](docs/EVAL.md) has the definitions, what each fix changed, how
the cutoffs were chosen and every known miss.

    npm run dev
    npm run eval                                   # app must be running
    npm run eval -- --url http://localhost:3210    # if it is on another port

## The language-model parts

    OPENAI_API_KEY=... npm run embed    # rewrites data/embeddings.json after a reseed
    PARSER=rules npm run dev            # force the rule parser
    RANKER=keywords npm run dev         # force keyword ranking (or RANKER=embeddings)
    npm run eval -- --parser rules --ranker hybrid   # score any mode on one server

`data/embeddings.json` is committed, so with a key set the embedding ranker
works straight away. The LLM's output is never trusted as is: it is clamped to
the schema, its numbers are checked against the rule parser, and any error
falls back to the rules. Defaults are `gpt-4o-mini` and
`text-embedding-3-small` at 256 dimensions; both were accepted by the API on 20
Nov 2026.

## Photos and clips

Every photo and clip was generated on Higgsfield for this demo and saved in
`public/creators/<id>/` (`1.jpg` to `5.jpg`, and `clip.mp4` for the creators
the demo briefs surface). Two profiles carry six more posts and photos
(`6.jpg` to `11.jpg`). Photos are listed newest post first, and a clip takes
the place of the photo it was animated from.

    python3 scripts/media_prompts.py    # writes data/media_prompts.json: the prompts for every creator
    python3 scripts/apply_media.py      # points data/creators.json at the files; run after `npm run seed`

`scripts/media_prompts.py` is the record of how they were asked for. Each
creator gets a distinct look from a per-creator seed. Five of their six posts
are illustrated, each from a hand-written scene for that caption (81 scenes),
so the photo in quick look matches the post text beside it. A first portrait
fixes the face; the other photos reuse it as a face reference (Nano Banana
Pro); clips are five seconds with sound (Kling 4.0 Flash). Every set was
looked at on a contact sheet before it was kept. The first round of portraits
(Soul 2.0) mostly failed that check, with app chrome drawn onto the image and
garbled lettering on products, so all of them were regenerated from the same
face with different wording; the script's docstring has the details.

## Layout

    scripts/seed.py              dataset generator (stage, audience, notes)
    scripts/eval.py              parser, P@5 and recall eval
    scripts/eval_queries.json    56 test briefs
    scripts/embed.py             embeddings for profiles, posts and notes
    scripts/media_prompts.py     prompts for the AI-generated photo sets
    scripts/apply_media.py       links the files in public/creators to the data
    src/lib/parse.ts             rule parser, LLM parser, output validation
    src/lib/search.ts            filters, keyword ranking, roster-first grouping
    src/lib/fuzzy.ts             typo tolerance
    src/app/api/search           POST { query } or { filters }
    src/components/CreatorCard.tsx   card, scrub preview, placeholder frames
    src/components/QuickLook.tsx     profile view: photo or clip, post, comments, notes
    src/components/FilterPanel.tsx   sidebar: sort and every filter
    src/components/FilterChips.tsx   how the brief was read, as removable chips
    src/components/ui                shadcn components
    src/app/globals.css          design tokens at the top
    docs/EVAL.md                 eval results (docs/eval-runs has the raw output)
    docs/DEMO.md                 two-minute demo script

## Deploy

Push to GitHub and import into Vercel. With no environment variables it runs
the rule parser and keyword ranking. Set `OPENAI_API_KEY` there to turn on the
LLM parser and hybrid ranker.
